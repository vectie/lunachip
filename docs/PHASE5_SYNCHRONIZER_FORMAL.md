# Three-stage synchronizer formal evidence

The Phase 5 synchronizer formal gate proves a bounded, two-state digital model
of the public LunaWire three-stage bit synchronizer. It reuses the exact pinned
Yosys, SymbiYosys, and Bitwuzla lock and the existing isolated runner. There is
no copied Phase 5 runner.

## Phase-neutral runner boundary

The historical scripts/phase4-yosys-run.sh path remains because Phase 4
receipts and execution manifests bind that name. Its typed-artifact calls now
go through scripts/formal-artifact-cli.sh. That CLI exposes only generic
verify and collect operations. Canonical regeneration is selected by the typed
source-set family registry in validation/formal; the runner does not know
about synchronizer fixtures. The runner has one separately documented,
digest-bound asynchronous-FIFO sharding hook; synchronizer tasks stay on the
generic formal execution path.

The Phase 4 generate command, four fixture names, five task names, source-set
grammar, task schema 1, emitted RTL, harnesses, and all generated bytes remain
unchanged. scripts/formal-bundle-selftest.sh generates the Phase 4 tree twice,
compares it byte-for-byte, then verifies every Phase 4 and Phase 5 task through
the same runner-facing CLI. It also proves that post-generation source
tampering is rejected.

## Exact timing contract

Each synchronizer task uses formal task/result schema 2:

- one logical scheduling interval is two formal-engine steps;
- source and destination clocks are exact named bindings to IR domains 0 and 2;
- a high clock must transition low at the next scheduling interval;
- each clock may remain without a rising edge for at most three intervals;
- coincident source/destination edges are legal;
- coincident edges update from one atomic global pre-state.

Requested next clock levels are captured on the positive edge of the formal
step clock and committed together on its negative edge. The DUT and independent
reference pipeline therefore observe the same pre-state when both clocks rise.
The source is an ordinary source-domain register feeding the declared
three-stage destination-domain synchronizer. Reset is active-high and
synchronous to the destination domain; its first destination edge is asserted,
and it then deasserts.

The four named assertions are:

1. pipeline_matches_previous_destination_samples;
2. synchronous_reset_clears_all_stages;
3. output_changes_only_on_destination_edge;
4. stable_source_converges_within_three_destination_edges.

coincident_source_destination_edge is a separate bounded cover. The valid
fixture has one bounded safety task and one cover task. Three isolated negative
fixtures corrupt only the pipeline, destination-edge, or convergence predicate.
Each negative execution manifest declares exactly one stable expected-failure
label. The runner rejects an absent label, any different/additional assertion
label, any result status other than the declared pass/fail status, and any
bounded failure without exactly one retained counterexample trace.

## Gate and claim boundary

Run the no-Docker checks with:

    scripts/formal-bundle-selftest.sh
    scripts/phase4-yosys-selftest.sh
    scripts/phase5-synchronizer-formal-selftest.sh

The focused synchronizer selftest reuses the shared adversarial receipt,
repository/artifact-manifest, and typed-formal-artifact suites. It also runs a
deliberately rejected bind-transport preflight without contacting Docker. That
failure must retain a strict incomplete receipt with the exact nonzero command
status and must not publish passing evidence. Source-level dependency checks
bind the gate to its runner, validator, artifact CLI, selftests, shared
libraries, schema manifest, fixed negative labels, and exact public matrix.

Run the pinned formal matrix with:

    scripts/phase5-synchronizer-formal-gate.sh [EMPTY_RUN_ROOT]

The gate requires five exact task outcomes: one bounded pass, one coincident
edge cover witness, and three isolated reachable counterexamples. Missing,
multiple, wrong, inconclusive, and tool-error evidence fails closed.

The gate accepts only the volume transport and defaults to it. Before checking
the Docker daemon or pinned provider, it creates an immutable incomplete
receipt. Every executable preflight and matrix operation writes a uniquely
receipt. Every explicitly logged tool/provider preflight and matrix subprocess
writes a uniquely named `COMMAND` record with its exact exit status.
Deterministic repository capture, provider-field extraction, receipt assembly,
and manifest assembly run inside the fail-closed lifecycle; their outputs are
bound by resulting digests rather than represented as child commands. Provider
provenance binds the Docker context and daemon output, locked OCI platform,
manifest digest, config digest, and volume transport.

Repository inputs and Git status are captured before execution and compared
byte-for-byte with end snapshots. The canonical repository manifest includes
safe internal symlink targets and hashes their resolved regular files. The
gate separately pins and rechecks every directly used runner, validator,
helper, selftest, shared library, and the complete pinned Yosys schema tree.

After each of the five runner calls, the gate independently verifies the typed
result, Phase 4 receipt, execution-manifest binding, result digest, tool and
status digests, complete `outputs.sha256` inventory, and the one retained
witness or counterexample when required. The three negative fixtures are
matched to fixed property-label constants rather than accepting any generated
non-`none` label.

All generated bundles, task outputs, transport receipts, command logs,
repository/status snapshots, and schema/bundle manifests live under one
artifact tree. A canonical manifest outside that tree binds every regular
artifact and rejects symbolic or special files. Only after repository, bundle,
dependency, matrix, receipt-grammar, and artifact checks pass does the gate add
`END` and atomically publish `STATE pass`; failures retain only the incomplete
receipt and logs.

This is bounded digital functional evidence. It does not model analog
metastability and does not claim MTBF, physical placement, routing adjacency,
timing closure, or silicon reliability. Those exclusions are recorded in both
the source set and aggregate evidence.
