# PRX100 BF16/FP32 banked loading — 2026-10-17

FPDDR1.1 is programmed through CPU_TAG on the PRX100-D. The same selected
Qwen3-0.6B projection completes in **163.773 µs** median warm hardware time,
compared with **307.123 µs** for a fresh FPDDR1.0 baseline: **1.875× faster**,
or **46.675% less latency**. Both campaigns pass **106 projections /848 FP32
outputs**, bit for bit against an independent CPU reference. The integer core
and all existing FP profiles remain unchanged;274 pre-existing production and
interface identities match the saved inventory.

## Change and numerical scope

The [banked-loading contract](../PRX100_FLOATING_POINT_BANKED_LOADING.md)
adds a separate `banked_dot_product()` constructor and `prx100_fpl` target.
The MoonBit hardware graph emits canonical IR and SystemVerilog; pinned Vivado
synthesizes, places and routes that RTL for the FPGA. One accepted load edge
now writes a shared BF16 activation and eight independent BF16 weights into
all eight operand banks. Eight512-word weight caches replace the previous
single4096-word cache without increasing capacity. Synchronous cache reads
and registered half-word selection feed1024 parallel loads plus one drain edge.
Packing takes1,025 cycles instead of8,193. The multiplier, FP32 accumulator,
arithmetic ordering and5*K+4 compute schedule are unchanged. The public FP
interface adds only the new constructor; existing constructor signatures remain
byte-identical. DDR bridge, storage layout, JTAG bursts, ownership and batches
retain the prior contract; ABI version is0x00010001.

The fixture is Qwen/Qwen3-0.6B revision
`c1899de289a04d12100db370d81485cdf75e47ca`, layer0 q_proj channels0..7,
K1024, with normalized embedding activations for token IDs42,100,1000.
Fixture SHA256 is`409ca5210ca8a10a2799f66590ab0ccee51f1cc501d8dc738a1334a71dfe225e`;
the24-job operand/reference file is
`eecb0a30731ce6645ef53a897c97aaa50a3e1d94399387c89b3dae1cb799ed8c`.
Each CPU reference multiplies BF16 operands, rounds each product to FP32 RNE,
then adds in increasing K order with a separately rounded FP32 addition.
This is a selected eight-channel projection, not full-model inference.

The loader saves exactly7,168 cycles /143.36 µs per projection. Small residual
hardware differences reflect DDR response timing. In the new48-job batch,
each projection spends40.754 µs in DDR states,20.500 µs packing,102.500 µs
waiting for the core (including102.480 µs arithmetic), and0.020 µs launching.
The cold3-job batch takes40,694 cycles /813.88 µs. The whole new campaign,
including uploads, guards and input readbacks, takes2.304878 s after programming.

JTAG remains the host bottleneck. The observed batch48 host improvement is
only1.024× and does not establish a repeatable transport speedup. The payload,
burst structure and readback work are identical. The new single warm projection
takes21.933 ms through all result/counter reads despite163.56 µs hardware time.

The resident scalar MoonBit/Wasm CPU loop measures67–69 µs per eight-output
projection, median68 µs over five1,000-iteration samples, with operands decoded
before timing. Complete warm FPGA execution remains2.41× slower than this
scalar loop. This CPU reference is not optimized BLAS. FP32 result accuracy
against higher-precision arithmetic is unchanged by the loader optimization.

Linux and Mac audits independently reconstruct operands from the logged DDR
writes and recompute all848 results per campaign; their audit JSON is
byte-identical. All input bytes and24 boundary guard words are read back twice.
Cache, DDR beat, logical load, packing and compute counters pass. A consistent
one-bit corruption in both result-table expected/actual values and the matching
raw DDR read is rejected by the independent CPU audit.
