# PRX100 BF16/FP32 arithmetic pipeline — 2026-10-17

FPDDR1.2 is programmed through CPU_TAG on the PRX100-D. The same selected
Qwen3-0.6B projection now takes **82.00 µs of arithmetic**, compared with
**102.48 µs** in FPDDR1.1. Warm complete hardware latency falls from
**163.760 µs to 143.313 µs** median: **1.143× faster**, or **12.486% less
latency**. Both fresh matched campaigns pass **106 projections / 848 FP32
outputs**, bit for bit against an independent CPU reference. The integer core
and all existing FP profiles remain unchanged; all **299** protected production
and interface identities match the pre-task inventory.

## Arithmetic and workload

The [arithmetic contract](../PRX100_FLOATING_POINT_ARITHMETIC.md) adds a separate
`fast_banked_dot_product()` constructor and `prx100_fpa` target. MoonBit hardware
construction produces canonical IR and SystemVerilog, then pinned Vivado
synthesizes, places and routes the FPGA design. Magnitude ordering and alignment
share the first accumulator stage; add/subtract, normalization and round/pack
occupy the next three. The BF16 multiplier retains its three stages. The new
adder's expression text compares exactly to the old adder after removing only
the two initial operand registers and renaming the private function.

The core issues every four cycles instead of five, preserving one running sum
per lane and increasing-K accumulation order. The first operand issues on
active cycle 5, and completion drains the last operation. Latency is exactly
`4*K+4`: 4,100 cycles for K1024 at 50 MHz, versus 5,124 previously. Each BF16
product is rounded separately before FP32 RNE addition; accumulation remains
non-fused. Canonical NaN, signed-zero, gradual-underflow and reset rules are
retained. The banked loader still takes 1,025 cycles. DDR storage, bridge,
transport and batch scheduling are unchanged; MMIO version is `0x00010002`.

The unchanged fixture is Qwen/Qwen3-0.6B revision
`c1899de289a04d12100db370d81485cdf75e47ca`, layer 0 q_proj channels 0..7,
K1024, normalized embedding activations for token IDs 42, 100 and 1000.
Fixture SHA256: `409ca5210ca8a10a2799f66590ab0ccee51f1cc501d8dc738a1334a71dfe225e`.
The 24-job operand/reference file is
`eecb0a30731ce6645ef53a897c97aaa50a3e1d94399387c89b3dae1cb799ed8c`.
This evidence covers the selected eight-channel projection, not full-model
inference or model accuracy/perplexity.

## Matched physical measurements

Both campaigns ran after CAD became idle, on the same board and Linux guest,
with 50 MHz core, 100 MHz DDR UI and 1 MHz JTAG. Each contains 16 batches,
91 full K1024 projections and 15 prefixes at K1,2,3,16,1023. Warm medians use
six 3-job batches; batch48 is one launch per profile. Hardware counters include
DDR staging, BRAM loading, core execution and DDR result writes. Host completion
also includes polling and all result/counter readback.

|Measurement|Fresh FPDDR1.1 baseline|FPDDR1.2 arithmetic|
|---|---:|---:|
|FP arithmetic, eight outputs|102.480 µs; 5,124 cycles|82.000 µs; 4,100 cycles|
|BRAM-to-core loading|20.500 µs; 1,025 cycles|20.500 µs; 1,025 cycles|
|Warm hardware completion, median|163.760 µs|143.313 µs|
|Warm hardware range|163.673–163.880 µs|143.293–143.380 µs|
|Warm 3-job host completion, per-job median|9.433 ms|9.271 ms|
|Batch48 hardware total|7.85878 ms|6.87822 ms|
|Batch48 host through all results/counters|55.672 ms|49.414 ms|
|Batch48 amortized host completion|1.15983 ms/job|1.02946 ms/job|
|Upload identical 22 KiB payload|359.830 ms|364.801 ms|
|Read back identical payload|378.027 ms|371.023 ms|

Arithmetic saves exactly 1,024 cycles / 20.48 µs per full projection, a 19.984%
reduction and 1.250× compute speedup. Residual total-cycle differences reflect
DDR response timing. The new batch48 averages 40.756 µs in DDR states,
20.500 µs loading, 82.020 µs waiting for the core (including 82.000 µs
arithmetic), and 0.020 µs launching per projection. The cold 3-job batch takes
37,647 cycles / 752.94 µs, versus 40,722 cycles / 814.44 µs in the baseline.
The entire new campaign takes 2.253938 s after programming, including uploads,
input readbacks, guards and control checks.

JTAG remains the host bottleneck. Warm per-job host ranges overlap:
9.047–9.948 ms baseline and 8.876–10.665 ms new. The single observed batch48
host speedup is 1.127×; it is not a repeatability claim for the transport.
Payload size, burst shape and readback work are identical. The new single warm
job takes 29.195 ms through all result/counter reads despite 143.34 µs hardware
execution. No transport bandwidth improvement is claimed.

The resident scalar MoonBit/Wasm CPU reference measures 67–68 µs per
eight-output projection, median 68 µs over five 1,000-iteration samples, with
operands decoded before timing. Complete warm FPGA execution remains 2.11×
slower than this scalar loop. This is a reference-loop comparison, not an
optimized BLAS benchmark.

Linux and Mac audits independently reconstruct operands from raw logged DDR
writes and recompute every output. Their audit JSON is byte-identical. All
input bytes and 24 boundary guard words are read back before and after jobs;
cache, DDR, load, compute and completion counters pass. A consistent one-bit
corruption in the result table's expected/actual fields and matching raw DDR
read is rejected by the independent CPU audit.

## Qualification

- Initial six targeted tests pass, including 20,200 streamed arithmetic cases
  against CPU FP32 results, special values, cancellation and random bit patterns;
  boundary-length, repeated, busy-ownership and reset-cancellation core jobs;
  and coupled Qwen DDR tests. `moon info`, `moon fmt`, native check with denied
  warnings and all **1,218 native tests** pass. Final 16-file re-export is
  byte-identical to the physical build inputs. Existing public FP signatures
  are unchanged; only the new constructor is added.
- Actual emitted core and controller RTL each match pinned Verilator 5.050
  over **46,261 observed cycles**, including 48 CPU-exact Qwen results, cold/warm
  caches, ready stalls, DDR gaps, AXI address/data skew and rejected host
  transactions. Native fault tests additionally cover watchdog/DDR faults,
  malformed response drain, reset and publication blocking. Both designs pass
  pinned Yosys 0.68 synthesis. No lint waivers were introduced.
- BMC32 passes 14 controller and 23 core control/counter/ownership/result-hold
  assertions. The inverted-load negative fails `p_fault_no_load` at step 3;
  tied-low core START fails `p_start_busy` at step 3. All 32 raw helper functions
  pass exhaustive two-state combinational equivalence. These are scoped
  control/helper checks, not unbounded arithmetic, DDR or job-completion proofs.
  The byte-identical DDR bridge retains its previous qualification.
- Ten owned formal volumes were removed only after sealed SHA256 inventories
  and full recopy kind/name/byte comparisons. The protected eight remain exact;
  [cleanup map](prx100-fpa-cleanup-20261017.json).
- Pinned Vivado 2025.2 build 6299465 and qualified MIG geometry/XCI. Route a1
  missed hold by 0.119 ns. Repair a2 reduced that to one 0.038 ns bridge-path
  violation; repair a3 closes setup **+0.958 ns**, hold **+0.047 ns**. All three
  attempts are retained. RTL, clock constraints and timing exceptions are
  unchanged throughout, and each source checkpoint's identity is checked.
  No failed candidate was programmed.
- All **2,998 core FD clock pins** use 20 ns `clk50`. All 12 unfiltered bus-skew
  constraints pass, minimum slack **19.274 ns**. DRC has no errors or critical
  warnings. The existing MIG CDC-10 reset advisory remains unsuppressed; the
  pinned vendor path has 15-stage asynchronous-assert/synchronous-release reset.
  This is digital timing evidence, not an analog CDC/MTBF proof.
- Whole-target resources: **16,319 LUT, 11,124 FF, 15 BRAM36 equivalents, 0
  DSP48**, versus 16,198 LUT and 11,638 FF with the same memory/DSP capacity in
  FPDDR1.1. The arithmetic change uses 121 more LUTs and 514 fewer registers.
