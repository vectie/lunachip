# PRX100 BF16/FP32 DDR3 projection — 2026-10-17

The FPDDR1.0 bitstream is programmed through CPU_TAG on the PRX100-D.
All **106 projections / 848 FP32 outputs** match an independent scalar CPU
reference bit for bit. This includes 91 full K1024 projections and 15 short
prefixes, across 16 cold, warm, repeated and autonomous batch launches.
The integer core, integer target, existing floating-point arithmetic/core and
FP1.1 BRAM target remain unchanged: 253 production/interface identities match
the pre-task inventory.

The [target contract](../PRX100_FLOATING_POINT_DDR.md) defines the storage,
ownership, reset, ABI and cycle-counter boundaries. The implementation uses
MoonBit hardware construction → canonical IR → SystemVerilog → Vivado → FPGA.
The separate target adds a weight cache, activation cache, BRAM packer and batch
sequencer around the unchanged eight-lane BF16 multiply / FP32 RNE core and
unchanged qualified 50/100 MHz DDR bridge. Vendor JTAG AXI4 and conversion-mode
AXI4-to-Lite IP provide up to 256-beat host bursts.

The fresh FP1.1 BRAM baseline passed40 jobs /320 outputs on the same board.

Input upload for the same three-vector workload is **350.75× faster**, combining
shared weights, fewer transmitted bytes and AXI bursts. The48-job launch reduces
amortized host time by **46.39×** relative to the individual-job baseline median.
This is batching throughput, not a46× reduction in single-job latency. Six warm
3-job batches give9.576–10.509 ms/job host completion, median10.019 ms/job.

Warm hardware completion is307.06–307.18 µs/projection. In the48-job batch it
comprises40.733 µs DDR states,163.860 µs BRAM packing,102.500 µs core waiting
(including102.480 µs arithmetic), and0.020 µs launch. Packing is now the largest
hardware cost. A cold3-job K1024 batch takes1.244160 ms total. Cache hits remove
128 streamed reads /16 KiB weights per batch; each job still fetches2 KiB
activations and publishes32 bytes of FP32 results to DDR.

The fresh resident scalar MoonBit/Wasm CPU reference measures67–68 µs per
eight-output projection, median68 µs over five1000-iteration samples. The FPGA's
complete warm hardware path remains4.52× slower than this CPU loop. These are
scalar reference timings, not optimized BLAS timings. The baseline campaign ran
while one Vivado CAD thread was active; the new board and CPU campaigns ran
after CAD became idle. Reported JTAG timings include observed host/tool overhead.
The full new106-projection campaign, including upload, readbacks, guards and
control checks, took2.260698 s after programming.
