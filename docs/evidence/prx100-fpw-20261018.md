# PRX100 JTAG bulk-transfer host data handling — 2026-10-18

Buffered host data handling reduces median upload time **49.853→33.044 ms**,
both complete actual input readbacks **133.537→118.584 ms**, and application
time **353.897→326.303 ms**. These are fresh same-bitstream measurements;
every compared output matches the CPU reference. Native checks: moon info/fmt, native deny-warning check and all **1,225 tests pass**; all16 re-exported hardware files match exactly.

The experiment changes host data handling on the same FPDDR1.3Q bitstream and
BF16/FP32 Qwen3-0.6B layer-zero q_proj channels 0–7, K=1024, three activation
vectors. Both profiles retain the preceding coalesced warm-request policy,
all 106 projections and 848 actual output words, complete input readbacks and
all 34 counters per physical batch. The integer and FP hardware remain unchanged.

See [the bulk-data contract](../PRX100_JTAG_BULK_DATA.md) for explicit trace
markers, write-submission semantics, actual-readback requirements and timing.

The selected comparison uses five fresh interleaved runs per `queue` and
`buffered` policy, with the same coalesced warm campaign: 106 projections and
848 output words per run. Each profile checks 530 projections / 4,240 output
words, or **8,480 compared words**. A separate first series compares five
`queue` and five `lean` runs; its additional 8,480 outputs and timings are
retained as exploration. Each series has a separate final qualification, and
one earlier pilot is excluded from statistics. There are 23 retained board
roots, 19,504 checked output words in total, and 154 matching Linux/Mac JSON
audit pairs for the 22 non-pilot campaigns.

Upload improves 33.72% (1.509×); both actual input readbacks improve 11.20%
(1.126×); their combined transfer interval improves 16.23% (1.194×). Application
time improves 7.80% (1.085×). Every paired upload and combined transfer interval
improves. Readbacks regress in pairs 1 and 4, and application pair 1 regresses
358.761→380.446 ms. Application/readback timing ranges overlap, with all samples
retained. The readback sum is calculated for each run before taking its median;
it is not the sum of the separate medians. No statistical-confidence or tail
claim is made, and historical reports are not substituted for the fresh baseline.

The first `lean` series removes write-object echoes and batches read-property
fetches. It improves upload 50.753→39.037 ms but does not establish readback or
application improvement: before-execution readback 61.876→65.803 ms and
application 334.043→360.566 ms regress in median. This motivated the separately
measured buffered variant, which also batches trace writes, removes dummy read
request words and appends collected values without repeated concatenation.
Both series remain in `metadata/summary.json`; only second-series paired runs
support the selected buffered numbers above.

All actual DDR traffic is retained: 17,796 read words and 11,292 write words per
campaign, including 16,896 actual operand-readback words, every 848-output result
and all guards. The 374 counter words (34 for each of 11 physical batches), error,
cache, drain and overlap checks remain. Actual upload remains 22,528 bytes, and
all 106 projections, all vector/order semantics and the preceding six-request
warm coalescing are unchanged. JTAG stays 30 MHz; the physical wire format,
transaction queue capacity and FPGA clocks are unchanged. The improvement is
in this validation driver's host data handling, not FPGA arithmetic or physical
link bandwidth.

The buffered path obtains a list of read DATA properties and checks exact
transaction/value counts, every 256-word shape, address and returned word. It
buffers each bulk group's trace into one write per stream. Queued operand
writes record intended submitted data with `GROUP_SUBMITTED` and `-` in the
actual-data field; reads without an input payload use `GROUP_READ_DATA` and
`-` in the request field, retaining every actual word. No absent object echo or
dummy request field is presented as an observation. MMIO, serial writes and
completed output/counter reads retain their original checks and formats.

Correctness rests on actual memory: before timing the upload, each operand
word is complement-poisoned and physically read back. Actual model writes must
replace that verified poison, and every model word is read before START and
after the workload. The independent CPU audit reconstructs intended writes and
requires every actual read to match; every result is recomputed from that
source-bound model. A lost/corrupt submitted write cannot be hidden by omitting
an object echo. Only final group RRESP/BRESP visibility is claimed, as before.

The new bulk audit checks all ten operand groups and all 110 transactions,
exact per-policy tags, observed source-instrumented property-call counts, all
returned data shapes, and complete before/after timer inclusion. Together with
CPU/group/timing/cache/launch/logical-warm audits, all 154 Linux/Mac JSON pairs
agree byte-for-byte across both series and final qualifications. Twenty intended
negative controls reject poison/model-submission corruption, actual-read data
corruption/coverage loss, invalid tag/direction, write range, fabricated echo,
property/value counts, timing, result, descriptor, DONE/error and cache faults.
The original wrong-tag fixture was rejected at hex parsing before its intended
operation check; its failed harness attempt remains preserved. A corrected
fixture supplies valid request words and reaches the intended rejection, with
no validator weakened. These are trace mutations, not hardware fault injection.

There is no resident-compute improvement: the resident timer median regresses
1.95%, and the unchanged 48-job host case measures 17.952→18.093 ms with
overlapping ranges. Arithmetic remains 4,100 cycles / 82 µs per full projection;
warm 48-job hardware throughput remains about 83.3 µs per projection. Fresh scalar
CPU reference is median 68 µs (67–74µs, five 1,000-iteration resident-operand runs).
The selected eight-output projection remains slower than the CPU end to end;
full Qwen inference and model-serving integration are not established.

Timing includes the actual upload, both full actual readbacks, all 106
projections and final guards. It excludes Vivado startup, programming and CPU
reference preparation. Post-run group-handling totals include all poison and
actual operand groups, while the application timer starts after verified poison.
The new after-execution readback timer includes both group transfers and local
verification, and is checked against their summed group durations.
