physical A/B reduced median FPGA projection latency **0.53596→0.48102 ms**:
**10.25% lower, 1.11× faster**. All 20 jobs on each image matched the CPU
reference. The portable word-read core, its ordinary/normalized RTL and name
manifest remain byte identical to target 1.4; 209 protected source/interface
identities also remain unchanged. Arithmetic and clock rates are unchanged.

## What changed

The [target contract](../PRX100_DDR_STAGING.md) adds `request_line` and
`response_last` at the internal DDR bridge boundary. A job read owns one
aligned 16-byte request and four ordered 32-bit response beats. The existing
34-bit response FIFO forwards those words directly into the inactive staging
region; the controller keeps its lease until the fourth accepted beat.
The source checks alignment, holds data/fault/last through backpressure,
and preserves cache invalidation and calibration-poison behavior. Host portal
reads and all writes retain their single-word response contract.

Each tile now makes **nine line requests instead of 36 word requests**, a
75% reduction at the sequencer/bridge boundary. Both versions already fetch
nine native DDR lines: **physical DDR read traffic is unchanged**. The gain
comes from removing repeated slow-domain request/acknowledgment cycles.
Each full projection stages the same 2304 words, using 576 read requests and
520 word writes. Descriptor writes remain 788, ordered completions 256,
partial writes 512, and compute cycles 1536. Core traffic remains 4352 word
reads, zero byte reads and 512 writes: 76 transactions per tile.

Early/missing last, an owned DDR fault, unowned response or calibration loss
fails closed before incomplete operands can be published. The acknowledged
staging prefix remains diagnostic state. Physical reset flushes the bridge
and both FIFO endpoints; a later START after success preserves resident DDR
buffers and rebuilds job/core state. Register version `0x00010005` distinguishes
the new protocol and the nine-per-tile read-counter meaning.
