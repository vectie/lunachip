# PRX100 BF16/FP32 readback decoding — 2026-10-18

The selected host path replaces repeated DATA regex scanning with checked
fixed-width slicing and fetches completed-result DATA properties as one list.
In a fresh five-pair comparison on the same FPDDR1.3Q bitstream, median total
actual readback falls **185.047→176.291 ms (4.7%)**, and the complete
106-projection application falls **348.876→323.771 ms (7.2%)**.
All **8,480 primary-comparison FP32 outputs** match the independent CPU
reference bit for bit. Integer and floating-point hardware remain unchanged.

The gain is modest and variable. One application pair and one total-readback
pair regress. Queued-read finish time itself regresses at its median; no
every-stage gain, improved JTAG wire bandwidth or bounded latency is claimed.
The first candidate has essentially tied application medians and regresses
total-readback/resident medians; its evidence is retained separately.

## Implementation and identical workload

The [readback contract](../PRX100_JTAG_READBACK_DECODING.md) describes
`scripts/prx100-fpy-{board,audit,groups,metrics,policy,launches,warm,bulk,readback,close}.mbtx`.
The first experiment uses `prx100-fpx` with string-map/xdigit validation and
regex chunking. The selected second experiment validates DATA width/hex,
then slices eight characters per word in reverse DATA order. An independently
validated underscore-field fast path is available; all actual board DATA
values in this campaign use slicing. Every campaign records 89 decoder calls:
66 operand burst values and 23 completed result/counter burst values.

The selected fast policy batches completed DATA property fetching, requiring
exactly one value per transaction. This reduces the source-level property
calls for those 23 objects from 23 to 11; these are property calls, not fewer
hardware reads. All 848 DDR outputs, 374 counter words, 16,896 physical operand
readback words and guards remain present. Queued operand properties already
use six calls in both profiles. Responses, launch/polling, descriptor/cache
checks, byte order, full poison/model-before/model-after reads and all fault
checks remain. Completed reads still follow observed DONE/error0 and execute
sequentially within a command; final group status does not prove every
constituent transaction's individual AXI response.

`c1899de289a04d12100db370d81485cdf75e47ca`, layer 0 q_proj channels 0..7,
K=1024, uses the same normalized embedding activations for token IDs 42/100/1000.

`eecb0a30731ce6645ef53a897c97aaa50a3e1d94399387c89b3dae1cb799ed8c`.

Each campaign has 106 projections/848 outputs in 11 physical batches:

## Fresh matched measurements

Primary series order is baseline-b1,fast-b1,fast-b2,baseline-b2,baseline-b3,
fast-b3,fast-b4,baseline-b4,baseline-b5,fast-b5, followed by final-sliced.
The first series and pilot are excluded from these statistics. Five samples
per profile are retained with no outlier removal. Values below are median
(minimum–maximum) milliseconds.

| Host measurement | Baseline | Fast |
|---|---:|---:|
| Full 106-projection application | 348.876 (314.46–407.389) | 323.771 (300.259–336.203) |
| Both full input readbacks | 124.163 (112.618–126.563) | 119.832 (106.156–128.316) |
| All completed-result/counter phases | 61.256 (52.705–85.47) | 57.905 (51.621–61.087) |
| Sum of those actual readback phases | 185.047 (165.323–212.033) | 176.291 (167.243–186.221) |
| Sum of 106 resident projection timers | 160.842 (128.479–210.418) | 139.629 (129.865–155.31) |
| Complete 48-job batch | 19.544 (16.261–26.543) | 18.687 (15.731–19.077) |
| Actual 22,528-byte upload | 37.199 (35.998–43.062) | 38.2 (32.68–39.637) |
| Queued-read finish phase, all six groups | 37.857 (34.384–43.972) | 42.716 (29.391–43.07) |

Application timing starts after complement poison has been physically
verified. It includes real upload, both full input readbacks, all 106
projections/checks/logging and final guards. It excludes FPGA programming,
Vivado startup and CPU-reference preparation. Resident timers include
configuration/cache handling, launch/poll/pacing, all results/counters and
local checks. Completed readback is the sum of results_us+counters_us;
it includes CPU result comparison. Total readback is the per-run sum of
both full input reads and those 11 completion phases, before computing the
median. It is not the sum of independently computed medians. Poison reads
and short initial/final guard/control reads are outside that aggregate;
final guards remain inside the application timer. Queued-read finish includes
property fetching, decoding and trace handling; it is not a pure decoder timer.

Only three of five paired completion aggregates improve, while four of five
application and total-readback pairs improve. Broad overlapping ranges and
host-call variance limit attribution of the end-to-end gain. The queued-read
finish median grows 37.857→42.716 ms despite the faster isolated decoder.
Upload median also regresses 37.199→38.200 ms; its implementation is identical.
Hardware arithmetic remains 4,100 cycles / 82 µs per K=1024 projection. A fresh
scalar CPU reference measures 67–68 µs, median 68 µs, over five 1,000-iteration
samples with operands decoded before timing. The FPGA host path remains
slower than that scalar reference. This is not a BLAS or full-model benchmark.

A separate pinned-Vivado microbenchmark of compact 256-word DATA measures
423.727→387.626 µs per decode over 1,000 iterations. This isolated result
excludes hardware/property/logging overhead; it does not replace board timings.

The first series's string-map candidate has application medians
330.955→330.953 ms, total-readback 177.571→181.778 ms and resident
142.844→152.672 ms. Its queued-read finish improves 39.422→35.805 ms.
These results are not substituted for the selected series's fresh baseline.

all byte-identical. Exact driver bytes and all 16 qualified hardware inputs
also match. Every one of the 89 DATA decoder invocations is accounted for.
