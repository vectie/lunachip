# PRX100 JTAG control/diagnostic batching — 2026-10-18

Host access batching and unchanged-descriptor reuse reduce measured median
resident 48-job completion from **30.250 to 21.425 ms** (**1.412×**, 29.174%
less time). Repeated three-job batches improve from **5.535 to 4.057 ms per
projection** (1.364×). Five interleaved campaigns per profile each pass **530
projections / 4,240 bit-exact CPU-reference outputs**. One paired run regresses;
these are median measurements with overlapping ranges, not a latency guarantee.

The selected driver is `scripts/prx100-fpc-compact-board.mbtx`, profile
`compact`. The [access contract](../PRX100_JTAG_CONTROL_BATCHES.md) documents
both measured approaches. The integer core and all first-party FP hardware
are unchanged. This task uses the existing qualified FPDDR1.3Q bitstream;
there is no synthesis or place-and-route rebuild.

## Implementation and ordering

The selected profile coalesces adjacent status/error registers into one
two-word read at byte address 8. It checks error=0 on every poll and requires
DONE=5 before reading completed results and all 34 counter words. This removes
the separate final error-read call. Identical K/job-count/vector-count tuples
remain installed across repeated STARTs; changed tuples are published in a
three-word burst before START. Six redundant descriptor publications disappear
from each sixteen-batch campaign: ten writes instead of sixteen. The prelaunch
cache read, every output, all counter words, cache invalidation, full input
readbacks and guards remain checked. Both selected and matched-baseline drivers
coalesce the three initial DDR base-register writes into one burst.

The prior depth-16 DDR groups, transaction reuse and 30 MHz JTAG remain in use.
They contain at most sixteen same-direction bursts, at most 256 words each,
with no 4 KiB crossing. The generic bulk interface still rejects MMIO. CPU_TAG
is `ME10E06D1010A`; runtime properties check both queues equal 16. FPGA identity,
source/bit qualification, DONE and CRC are checked at programming. No flash is
written. Exclusive ownership of the target is required during descriptor reuse.

An initial explicit-queue candidate, retained as `prx100-fpc-board.mbtx`,
queues the descriptor write followed by START, then queues results, counters
and error after observed DONE. It passes its complete checks, but tiny-group
Vivado overhead limits its benefit. In its separate five-run comparison,
application median changes 508.064→449.820 ms, warm three-job time per projection
5.680→5.067 ms, resident 48-job time 26.062→23.291 ms, and single-job time
17.530→17.447 ms. Median calls fall 156→108, demonstrating why call count
alone is insufficient to choose the faster strategy. The compact comparison
below uses a fresh interleaved baseline; the two comparisons are not pooled.

Vivado's queued `GROUP_OKAY` records only the observed final group response.
It does not prove each queued AXI request's individual response. Full data,
CPU, counter, error and group-coverage checks supply separate behavioral
evidence. The selected MMIO reads/writes retain their ordinary burst-response
checks; MMIO is not queued in the selected compact profile.

## Fixed workload and independent checks

Model: Qwen/Qwen3-0.6B revision
`c1899de289a04d12100db370d81485cdf75e47ca`, layer-0 q_proj channels 0–7,
K=1024, normalized embedding activations for token IDs 42, 100 and 1000.
Fixture SHA256:
`409ca5210ca8a10a2799f66590ab0ccee51f1cc501d8dc738a1334a71dfe225e`.
Packed jobs SHA256:
`eecb0a30731ce6645ef53a897c97aaa50a3e1d94399387c89b3dae1cb799ed8c`.

An independent scalar reference reconstructs operands and installed descriptors
from raw DDR/MMIO writes. It performs BF16-input multiplication and separately
rounded FP32 accumulation in increasing K order. Every output read and every
result-table word must match this independently recomputed reference exactly.
Each campaign covers K=1,2,3,16,1023,1024; six repeated warm full batches;
warm 1/18/48-job batches; and final cold three-job execution. That is 106
projections, 91 full and 15 prefix projections, yielding 848 checked outputs.

Every model word is first poisoned with its complement and read back before
the actual value is written. Actual operands are fully read before and after
jobs: two writes and three readbacks per model word. All 24 boundary guards,
scratch words, cache state, completed index/vector, loaded/staged/read/write
counts, feeder/pending drain, overlap accounting and error status are checked.
Seven invalid bulk operations are locally rejected and five invalid device
accesses return SLVERR. The explicit-queue candidate also locally rejects six
invalid control shapes/phases before any transaction is created.

All twenty matched campaigns pass CPU, queue-group and timing audits on Linux
and macOS, with **60 JSON pairs byte-identical**. Two separate pilots also pass
and are excluded from statistics. Fourteen offline negatives are retained:
eight for the explicit-queue candidate (poison corruption, consistent raw/table
result corruption, oversized queue, inconsistent timing, reversed launch,
diagnostics before DONE, corrupted counter, corrupted error) and six for compact
(poison, consistent raw/table result, capacity, timing, coalesced error word,
stale descriptor). No negative emits a PASS receipt. The two phase/order
negative fixtures explicitly rebind the raw digest solely to exercise the
group validator past its hash-binding gate; they are not successful CPU audits.

## Matched compact-profile performance

Order: queue-b1, compact-b1, compact-b2, queue-b2, queue-b3, compact-b3,
compact-b4, queue-b4, queue-b5, compact-b5. All runs use the same bitstream,
board, guest, model, clocks and validation. No CAD job runs during measurement.

Resident time starts before descriptor/cache handling and ends after all
result, counter and error validation. It excludes programming, Vivado startup
and subsequent table logging. Compact reads error in the polling phase;
the baseline reads it after counters. Application time also includes the
actual 22,528-byte upload, both actual input readbacks, all 106 projections
and final guards. Qualification time additionally includes poison/initial
checks. No output or counter read is skipped to obtain the improvement.
