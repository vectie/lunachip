Fresh smoke a9 and accelerator a10 routed reset and CDC review, 2026-10-26

This additive review binds the actual `20261026-v20261-build-a9` routed checkpoint from ready-inputs `pblaze3-ready-inputs-20261026-2026-1-a5`. Vivado is 2026.1, SW Build 6511674, IP Build 6504888. The original build remains rejected and immutable: its exact-seven routed reset guard encountered fifteen endpoints and correctly stopped before a bitstream. The additional eight are physical-optimization copies of the existing PCIe `user_reset_out_reg`, rather than new reset consumers. This review does not constitute hardware, DDR-calibration, PCIe enumeration, or accelerator acceptance.

The candidate guard retains every prior synthesis/dead-output, PIPE synchronizer, status-source and vendor-release check. At route it discovers copies through Vivado's `get_cells -include_replicated_objects` on the exact original cell. It requires the exact parent, `ORIG_CELL_NAME=user_reset_out_reg`, `IS_ORIG_CELL=0`, `ORIG_REF_NAME=FDPE` and `PHYS_OPT_MODIFIED=FANOUT_OPT`; the original must be the original FANOUT_OPT cell. Each copy must be FDPE with the same INIT and supported clock/preset inversion properties, exactly C/CE/D/PRE input pins, and the same complete hierarchical net-segment sets on all four inputs. The complete boundary fanout must equal the original seven pins plus only those proven PRE pins. A wildcard name alone authorizes nothing. The actual a9 result is eight copies, named `user_reset_out_reg_replica` through `_replica_7`, all INIT=1 and with identical state transition inputs to the original.

The source seven-pin `reset-boundary.xdc` is unchanged (SHA-256 `f0622b8aa9e00f72e7adc23149e72d9ef1f7ea9e53fd0e1fdf6b9cee8963702b`). The actual routed `write_xdc` output shows precisely those eight additional PREs inherited under the same exact `-through pblaze3_i/transport_reset_gate/Res[0]_INST_0/O` boundary. There is no clock-wide exception and no payload endpoint added. This behavior matches AMD's 2026.1 [Physical Optimization Constraints](https://docs.amd.com/r/en-US/ug904-vivado-implementation/Physical-Optimization-Constraints), which describes copying timing exceptions to replicated cells; [`get_cells`](https://docs.amd.com/r/en-US/ug835-vivado-tcl-commands/get_cells) documents replication-aware selection. [Physical Synthesis Phase](https://docs.amd.com/r/en-US/ug904-vivado-implementation/Physical-Synthesis-Phase) documents FANOUT_OPT provenance. [Replication constraint guidance](https://docs.amd.com/r/en-US/ug903-vivado-using-constraints/Adjusting-Constraints-for-Synthesis-Logic-Replication) documents ORIG_CELL_NAME.

The independent reset-supervisor mapped snapshot proves three ASYNC_REG FDPE XPM stages and eight FDCE counter bits on the independent 20.000 ns `reset_clk50_pblaze3_clocks_0`, whose master is the primary 20.000 ns `clk_in1_50M`. Stage zero D is ground, Q0 feeds only stage one D, Q1 feeds only stage two D, and Q2 resets all eight counter CLR pins. The mapped counter retains the saturating 128-edge release behavior already validated against the canonical RTL and actual XPM model. Physical optimization absorbs inversions: the mapped health gate is LUT2 INIT=7, producing active-high fault; the final boundary gate is LUT2 INIT=D with I0=counter bit7 and I1=fault, implementing `!bit7 || fault`. All three XPM presets receive raw fault and the final boundary asserts immediately on raw fault. These polarity changes preserve the source's reset behavior; routed INIT=8 is neither expected nor required.

This construction follows the [PG054 asynchronous fundamental reset contract](https://docs.amd.com/r/en-US/pg054-7series-pcie/Resets) and its [minimum 1500 ns assertion requirement](https://docs.amd.com/r/en-US/pg054-7series-pcie/System-Interface). The independent 50 MHz hold exceeds 2.5 us. It does not depend on XDMA `axi_aclk`, which [PG195 states is not free-running](https://docs.amd.com/r/en-US/pg195-pcie-dma/Clocking-and-Resets). The vendor PIPE chain and synchronized status-source checks remain mandatory in the guard.

Actual independent timing reports show WNS +0.013 ns and WHS +0.014 ns, zero failing setup or hold endpoints, WPWS 0.000 ns and zero pulse-width failures. `check_timing` reports zero no-clock, unconstrained internal endpoint, multiple-clock, generated-clock and loop violations. Its eight pulse-width-clock entries identify GTX CLKRSVD checks, not failures. Missing input delay entries are eight DDR DQS inputs and asynchronous PERST; the remaining output entries are DDR reset and LEDs. The ordinary GPIO OOC 10 ns versus actual 4 ns warning does not establish closure itself; these final routed constraints time the connected GPIO at its actual clock.
