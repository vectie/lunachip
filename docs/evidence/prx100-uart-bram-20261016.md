# PRX100 physical UART + BRAM smoke test, 2026-10-16

The programmed PRX100 smoke image passes all29 physical UART transactions
at115200baud,8N1, with no flow control. Identify, eight patterned BRAM word
writes, reads before and after logical reset, and bounds/alignment rejection
all pass. Every32-byte response passes the existing MoonBit CRC/envelope
decoder and exact opcode, sequence, status and five-word comparisons.

This demonstrates the board's UART/control and4KiB BRAM aperture. It does not
establish a physical accelerator workload, Array8 execution, full-aperture
memory coverage, button-reset/power-cycle retention, soak reliability or the
complete Phase7 acceptance gate. Phase6 remains in progress.

## Board, configuration and connection

Both cables were detected on the Linux host on2026-10-16: CPU_TAG is
FTDI0403:6010/Digilent serial `ME10E06D1010`; USB TO UART is
CP2102 `10c4:ea60`, serial `0001`. After USB reconnection their host addresses
were bus1/device11 and bus1/device10 respectively. The stale task-owned FTDI
VM attachment was removed, then only these two identified devices were
attached to the existing xHCI controller. No VM restart was required. Host
USB node ownership was restored to root:root0664 after QEMU opened the devices.

The minimal Ubuntu22.04 guest lacked `cp210x`. Installing
`linux-modules-extra-5.15.0-198-generic` version `5.15.0-198.208` and loading
`cp210x` created the serial node. The package also installs its dependency
`wireless-regdb`; package/module details and installation output are retained.
These changes are confined to the isolated guest. No host package, udev rule,
service, repository, firewall or network configuration was changed.

The guest uses the identified path:

```text
/dev/serial/by-id/usb-Silicon_Labs_CP2102_USB_to_UART_Bridge_Controller_0001-if00-port0
```

After reconnection, the same qualified smoke image was reloaded through the
identified CPU_TAG cable at1MHz JTAG. Vivado2025.2 identifies `xc7a100t_0`,
IDCODE `0x13631093`, and reports DONE=1,CRC_ERROR=0 after programming.
Configuration is volatile; flash was not programmed. The image SHA256 remains
`203908ac91ad52c1b4cf77cc31667c5f392acb9aef8c5f89acca8858d275386a`.
The [build ledger](prx100-vivado-build-20261015.md) retains its routed50MHz
reports, source snapshot and bitstream. No portable core, RTL or bitstream
change was made for this board test.

## Reproduction and evidence

The unchanged [`prx100-board-smoke.mbtx`](../../scripts/prx100-board-smoke.mbtx)
verifies the bitstream, vendor pin and codec binary identities. It programs a
fresh campaign root, then runs the UART test against the discovered CP2102:

```text
moon run /work/prx100-board-smoke-20261016.mbtx -- program /work/builds/prx100-board-smoke-NEW_RUN
moon run /work/prx100-board-smoke-20261016.mbtx -- uart /work/builds/prx100-board-smoke-NEW_RUN /dev/serial/by-id/usb-Silicon_Labs_CP2102_USB_to_UART_Bridge_Controller_0001-if00-port0
```

Run inside the guest with `MOON_HOME=/tools/moon-baseline` and that toolchain's
`bin` on PATH. Use a new root each time; the test writes the listed words and
logically resets the shell. The runner refuses existing UART outputs and
stops on any mismatch, with no automatic mutation retries. Actual campaign:
`/work/builds/prx100-board-smoke-20261016-a1`.

The target check and all five target tests pass on the Mac; the standalone
driver remains formatted. Repository changes in this campaign are documentation only.
Unique programming/serial captures, installation/module records, exact driver,
connection log and receipts are retained in
`artifacts/prx100-uart-bram-20261016`, with a verified SHA256 inventory and
seal. Caches and credentials are excluded. Working originals, the earlier
programming archive and all previous sealed archives remain unchanged.
