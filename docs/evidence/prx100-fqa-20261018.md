## Change and rejected alternatives

The tested cached candidate uses dedicated launch transaction keys,skips redundant DATA updates when the dedicated payload is unchanged,and fetches all launch DATA properties in one call. It still checks every write-object echo,final direction response,status/error,DONE,output and counter. The baseline uses the same dedicated keys and common timing/logging; only payload reuse and property batching differ. Both use explicit AXI ID0 and sequential command lists for launch/completion.

Exploratory FQA serial/completion-read-queue/write-plus-read-queue pilots all pass848 outputs each; queued completion is not consistently faster and is not selected. Homogeneous read/write queues are kept separate: AMD documents independent directions and read-first execution for a mixed queued command. See [AMD PG174](https://docs.amd.com/v/u/en-US/pg174-jtag-axi). No mixed-direction queue is introduced.

The FQB cached pilot reused the ordinary transaction cache. An invalidation write changed the shared START object; the mandatory write-object echo rejected the final cold launch. Its source,Tcl,partial trace and failure logs are preserved. FQC separates launch objects and passes the same cold transition. A six-case exact-launch Tcl harness covers unchanged payloads,descriptor changes,ordinary-object isolation,malformed DATA count,changed write data and baseline behavior. The first mock incorrectly coerced singleton numeric strings; its failed inputs/logs and corrected mock are retained. The FQA completion auditor initially had a generated brace error; the failure and corrected audit replay on unchanged raw data are both retained.

Nineteen intended negative controls reject poison/result corruption,capacity/timing violations,error/descriptor/DONE changes,stale/invalidated cache certificates,poll schedule changes,decoder-path/data/phase/group/source corruption. These supplement all unchanged numerical and physical-traffic audits.
