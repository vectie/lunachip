# PRX100 repeated warm-request coalescing — 2026-10-18

Coalescing the six available warm requests reduces their complete measured
sequence time **57.238→13.358 ms (4.285×)**. Median application time improves
**400.200→362.511 ms (9.4%)**. All compared results match the CPU reference.
Native checks: moon info/fmt, native deny-warning check and all **1,225 tests pass**; all16 re-exported hardware files match exactly.

The experiment coalesces six simultaneously available identical warm three-job
requests into one 18-job hardware batch. It retains all 106 projections and 848
actual DDR outputs in the campaign, with all 34 counters per physical batch.
The integer core, floating-point hardware and qualified FPDDR1.3Q bitstream are
unchanged. This changes batching and can delay the first response; it does not
claim faster isolated three-job execution.

The workload remains Qwen3-0.6B layer-zero q_proj channels 0–7, K=1024, with BF16
weights/activations and ordered FP32 accumulation. See the
[warm-batch contract](../PRX100_JTAG_WARM_BATCHES.md).

one 18-job batch, so total physical campaign batches fall16→11 while logical
requests stay unchanged. Warm counter words fall204→34, with one complete

existing sequencer's batch boundaries; this is not a pure transport-only gain.
