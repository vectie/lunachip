# PRX100 BF16/FP32 DDR and loading overlap — 2026-10-17

FPDDR1.3 is programmed through CPU_TAG on the PRX100-D. Double-buffered
operands allow DDR staging and BRAM loading for upcoming jobs to overlap the
current BF16/FP32 computation. The same selected Qwen3-0.6B projection averages
**83.313 µs per job in a 48-job batch**, versus **143.289 µs** in a fresh
FPDDR1.2 baseline: **1.720× throughput**, or **41.856% less hardware time**.
Both fresh campaigns pass **106 projections / 848 FP32 outputs**, bit for bit
against an independent CPU reference. All **325** protected production and
interface identities match their pre-task inventory, including the integer
core and existing FP profiles.

## Construction and ownership

The [overlap contract](../PRX100_FLOATING_POINT_OVERLAP.md) adds
`buffered_dot_product()` and the separate `prx100_fpo` target. MoonBit hardware
construction produces canonical IR and SystemVerilog; pinned Vivado synthesizes,
places and routes the physical design. Each of eight lanes now has two
1,024-word operand banks, doubling core operand capacity from 32 to 64 KiB.
An accepted START captures its bank. Loads may update only the inactive bank
while computation runs; simultaneous START/load is allowed for different banks.
Same-bank conflicts reject both actions.

A feeder stages DDR operands and packs them into a free bank. A separate
executor consumes prepared banks in order. Prepared-minus-captured jobs never
exceeds two, and a bank is reusable only after its result is captured. One held
eight-word result permits the next computation to start while writeback finishes.
If writeback stalls, a later completed core result waits intact until that slot
is free. A single DDR owner arbitrates reads and writes between transactions;
allocated request payloads remain latched through backpressure. Health and
protocol faults cancel computation and block publication until physical reset.

The FP multiplier and accumulator expressions are unchanged, with increasing-K
order, separately rounded products and FP32 RNE accumulation. Arithmetic remains
`4*K+4` cycles: **4,100 cycles / 82.00 µs** at K1024 and 50 MHz. Packing remains
**1,025 cycles / 20.50 µs** per job. DDR UI remains 100 MHz. MMIO version is
`0x00010003`; DDR layout, payload and transfer counts are unchanged.

Three-job median throughput improves 1.399×, with 28.508% less time per job.
The larger batch approaches the unchanged 82 µs arithmetic limit. This is
overlap across independent jobs: single-projection latency does not improve.
All measurements include the original job's accumulation dependency and order.

New stage counters are inclusive. In the 48-job batch, total cycles are
199,952; DDR activity is 97,795, packing 49,200 and executor ownership 196,848.
DDR/executor intersection is 95,717 cycles, packing/executor 48,175,
DDR/packing 1,125, triple intersection 1,125, and gap 1. Inclusion/exclusion
reconstructs the total exactly. Executor ownership includes 48 cycles beyond
196,800 arithmetic cycles. Subtracting all 48 from each intersection gives
conservative **actual-arithmetic overlap lower bounds of 95,669 DDR cycles
and 48,127 packing cycles**. Thus the observed overlap is with arithmetic,
including its pipeline, rather than merely a held completion.

Host completion through result/counter readback for the observed 48-job batches
is 59.517 ms baseline and 48.861 ms new, or 1.240 and 1.018 ms/job. The six
three-job host medians are 7.727 and 8.331 ms/job respectively. These are not
equal-diagnostic-work transport benchmarks: the new counter burst reads 34
words versus 16 previously, with the same transaction count. JTAG timing varies
and still dominates end-to-end time; no transport bandwidth gain is claimed.
The identical 22,528-byte payload uploads in 348.245/367.221 ms and reads back
in 366.425/370.394 ms (baseline/new). The new campaign takes 2.400478 s after
programming, including uploads, guards and control checks.

The resident scalar MoonBit/Wasm CPU reference takes 67–68 µs per eight-output
projection, median 67 µs over five 1,000-iteration samples with operands decoded
before timing. Even the FPGA's 48-job average remains about 1.24× slower than
that scalar loop. This is not an optimized BLAS comparison. The selected block
does not establish full-model inference, autoregressive decoding or model quality.

Linux and Mac audits independently reconstruct operands from raw logged DDR
writes and recompute every output; their audit JSON is byte-identical. All input
bytes and 24 boundary guard words are read back before and after execution.
Counters check exact transfer/load/arithmetic counts, final publication index
and vector, empty pending result and fully retired jobs. A consistent one-bit
corruption in expected/actual output fields and the matching raw DDR read is
rejected by the independent CPU audit.
