# PRX100 queued-read finish investigation — 2026-10-18

Validated fixed-width Tcl `scan` decoding replaces the preceding per-word
slicing loop. Across both retained series, queued-read finish median falls
**36.5485→14.2015 ms**, and total actual-readback median is
**181.209→172.3075 ms**. Complete 106-projection application
medians are **328.604→332.1605 ms**. All **16,960 matched FP32 outputs**
are bit-exact against the independent CPU reference. Integer and FP hardware
remain unchanged.

**No end-to-end speedup is demonstrated.** Combined application median is
1.1% slower, with 6/10 paired applications improving and overlapping ranges.
Queued-read finish improves in all 10 pairs (61.1% median reduction), decoder
time falls 75.1%, and total-readback median falls 4.9%. The result isolates a
substantial software-cost reduction while slower host command intervals in
unchanged launch/completion paths offset that benefit in the full workload.

## What the regression investigation established

The preceding FPX report observed queued-read finish medians 37.857→42.716 ms,
but its aggregate timer could not separate DATA fetching, decoding and logging.
Those historical logs cannot retroactively establish the precise cause of
that difference. This experiment instruments the preceding selected FPY
decoder and a new decoder with the same explicit phase boundaries.

The diagnostic prior pilot spends 30.500 of 36.043 ms in bulk DATA decoding,
versus 1.301 ms in DATA properties and 3.490 ms in residual trace/list handling.
The scan pilot reduces decoding to 8.056 ms and finish to 13.782 ms while
property fetching remains 1.213 ms. The per-word Tcl loop is the dominant
current software cost; property fetching is a small fraction of this finish
interval. These pilots diagnose the path and are excluded from matched statistics.

The selected decoder validates compact hexadecimal DATA directly, normalizes
separators only when needed, then uses a cached `%8s` format to obtain all
eight-character words in one Tcl `scan`. It checks the exact returned count,
normalizes case and reverses DATA into increasing-address word order. String
conversion retains leading zeros. Burst lengths remain 1–256. No physical read
or result/counter word is removed. See the
[host contract](../PRX100_JTAG_READBACK_FINISH.md).

A pinned Vivado Tcl 8.6.13 microbenchmark of compact 256-word DATA measures
388.594→90.737 µs per decode over 1,000 iterations (about 4.3×). Separated
DATA measures 219.727→125.148 µs. These isolated measurements exclude hardware,
property and trace overhead. Both decoders pass 256 valid data/order comparisons
and 20 malformed/width/Unicode/NUL/shape rejection invocations on local Tcl 8.5.9
and Vivado Tcl 8.6.13. The test directly includes the same generated decoder Tcl.

## Matched samples and timing scope

The initial series contains five interleaved pairs plus final-scan. Every
queued-read finish and both-input-readback pair improves, but application
medians 343.751→345.896 ms are essentially flat (+0.6%) and the unchanged
resident/control calls run slower. This motivates five additional pairs with
opposite first-run order, followed by final-repeat. Both series and all
regressions remain retained; no original observations or outliers are discarded.
The follow-up was added after seeing that variance; it was not part of the
original five-pair plan. Selection criteria were recorded before summary:
lower queued-read finish, decode and total-readback medians, satisfied by the
initial series and checked again over both series.

Finish partitions include response status, DATA fetch, decoder execution and
residual trace/list handling plus clock-probe overhead. Every partition sums
exactly to the original finish interval. The new profile log is written
after that interval and remains in outer timers. Common instrumentation
and helper dispatch are present in both profiles. This is a host optimization;
unchanged traffic and link rates do not establish faster JTAG wire bandwidth.

Total readback is each campaign's sum of both full input readbacks and the
results_us+counters_us completion phases, before computing medians. It
includes CPU result comparison, but excludes poison and short guard/control
reads. Queued-read finish covers all six operand groups, including poison,
so it is a different aggregate. Application timing starts after verified
poisoning and includes real upload, both input readbacks, all 106 projections,
checks/logging and final guards. Programming, Vivado startup and CPU-reference
preparation are excluded. Resident timers include configuration/cache,
launch/poll/pacing, all results/counters and local checks. The raw group
run_hw_axi intervals locate host/hardware command time separately from finish.
