# PRX100 complete Qwen3-0.6B layer — 2026-10-18

Layer 0 now runs entirely as MoonBit-constructed hardware on the PRX100-D:
input RMSNorm, Q/K/V projections, Q/K head normalization, RoPE, causal
grouped-query attention, stable softmax, output projection and residual,
post-attention RMSNorm, gate/up projections, SiLU gating, down projection and
the final residual. DDR3 supplies weights; FPGA scratch BRAM retains the KV
cache. The host supplies checkpoint assets, embedding inputs, immutable RoPE
coefficients and descriptors, then launches and reads results. No runtime CPU
normalization, attention or MLP intermediate is uploaded to the FPGA.

This completes one transformer layer, including cached decode. It does not
establish full-model text generation, all-layer scheduling, logits, sampling,
model quality or performance at long contexts. The first implementation favors
correctness and resource fit: it is slower than the scalar CPU reference.

## Precision and workload

The model is [Qwen/Qwen3-0.6B, revision c1899de289a04d12100db370d81485cdf75e47ca](https://huggingface.co/Qwen/Qwen3-0.6B/raw/c1899de289a04d12100db370d81485cdf75e47ca/config.json).
The layer follows the [Transformers v4.51.3 decoder equations](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/models/qwen3/modeling_qwen3.py):
hidden 1,024, intermediate 3,072, 16 query heads, eight KV heads, head dimension
128, RMS epsilon 1e-6 and RoPE theta 1,000,000. Seven matrix assets occupy
31,457,280 bytes; all 27 uploaded assets occupy 31,485,952 bytes.

Weights retain checkpoint BF16 values, expanded exactly for FP32 arithmetic.
Activations, products and ordered accumulations are FP32, with separate RNE
rounding for multiply and add. This is not framework BF16 activation rounding
or a fused/BLAS reduction order. There is no integer quantization. Reciprocal
and reciprocal square root use four FP32 Newton iterations; exponential uses
range reduction, a degree-eight polynomial and six squarings. Their explicit
domains and exceptional behavior are in the [target contract](../PRX100_QWEN_LAYER.md).
The declared CPU tolerance is `1e-4 + 1e-4*abs(reference)` per value.

The workload uses embedding inputs for token IDs 42, 100 and 1000, followed by
token 42 at position three. Context capacity is eight; the tested context is
four. The 2,025-descriptor full program includes HALT. Separate programs use
1,519 descriptors for three-token prefill and 507 for fourth-token decode.
START resets control/counters while preserving scratch and KV state.

## Physical numerical results

The board completed one cold and three warm four-token programs, followed by
separate three-token prefill and cached one-token decode: six layer launches,
20 token-layer executions. Each token stores 20 diagnostic stage tensors.
Actual readbacks comprise 400 stage tensors and 40 KV tensors, totaling
656,960 FP32 words, plus a five-word operator smoke test.

Two independent comparisons passed:

- Against the high-level scalar CPU reference, all 656,960 words pass the
  declared tolerance. Maximum absolute error across all stages/KV is
  **3.0517578125e-5**; 266,180 words are bit-exact. The 20,480 final hidden
  output words have maximum absolute error **2.86102294921875e-6**.
- Every readback word is bit-exact to the separate descriptor/arithmetic
  emulator, which models the declared FP32 rounding and approximate nonlinear
  operators. This exactness is not a claim of bit identity to mathematical
  exp/sqrt, PyTorch BF16 execution or arbitrary reduction orders.

Both the initial complete asset readback and the post-run complete asset
readback are byte-identical to the 31,485,952 uploaded bytes. All three uploaded
programs were completely read back and compared. Outputs and KV were poisoned
before their relevant tests. The independent audit checks raw binary arrays,
queue sequences, counters, program identities and timing; a second audit
binds the FPGA identity, configuration status, qualified bitstream, 15 source
files and all 441 Tcl comparison records. Six expected busy/invalid accesses
return SLVERR. Final state is DONE/idle, healthy, error zero and configuration
CRC error zero.

## Construction and implementation qualification

`designs/qwen_layer` constructs the arithmetic and sequencer in LunaWire;
`targets/prx100_layer` constructs its AXI controller. `cmd/prx100_layer` exports
canonical IR/SystemVerilog, fixtures, CPU references and arithmetic models.
Vivado 2025.2 performs synthesis, placement and routing for
`xc7a100tfgg676-2`. CPU_TAG serial is `ME10E06D1010A`; FPGA ID is `13631093`.
Programming is volatile; flash remains unchanged.

The instruction and scratch RAMs are each 32,768 words, with one explicit
scratch read port scheduled over two operand cycles. Preserved memory leaf
modules are themselves generated in LunaWire with the canonical ReadOld/
HoldLast semantics. This fixed the initial distributed-RAM overuse without
handwritten arithmetic or memory semantics. The Verilator module files
concatenate byte-for-byte to physical CAD's `core.sv`.

Final full-target utilization is **15,362 LUTs, 8,920 registers, 70.5 BRAM
tiles and 13 DSPs**. The final fully routed build has setup slack **+0.002 ns**
and hold slack **+0.015 ns**, zero failing setup/hold/pulse-width endpoints and
no DRC Error/Critical Warning. Vendor/design warning advisories remain. The
2 ps setup margin is tight and is a material limit of this qualified build.
All 1,134 actual core clock pins were checked at 40 ns. A post-route hold-fix
pass repaired the failed hold timing; no RTL, constraint or clock relaxation
was used for the final 25 MHz result.

Qualified guest build: `/work/builds/prx100-layer-vivado-20261018-hold-a1`.
Physical run: `/work/builds/prx100-layer-board-20261018-a1`.

## Validation and retained unsuccessful attempts

All 1,232 native tests pass in the isolated Linux validation workspace, including
seven new core/controller tests. `moon info`, `moon fmt`, strict native check and
strict native test completed there. The pinned Linux baseline uses moon
0.1.20261012, moonc 0.10.15+943464bfa. A validation-workspace-only override adds
`-D_GNU_SOURCE` and `-ldl` to the existing C allocation probe; original and
override manifests are retained. No repository integer/old hardware source
was changed for that environment adjustment. The current Mac SDK's full strict
check encounters 145 existing deprecation warnings; its logs are retained.
Final targeted checks and seven new tests pass on the Mac. SDK formatter
rewrites outside this task were restored to byte-identical captured originals;
the recovery maps and rewritten copies remain available.

The final physical core passes 101,373-edge LunaWave/Verilator differential
replay with 2,230,206 checked output words. Only 803 raw uninitialized memory
data outputs while their valid signal is zero are masked. The arithmetic RTL
also passes 100,000-edge differential replay and native FP32 bit checks.
Pinned Yosys 0.68 coarse memory-preserving synthesis passes; the arithmetic
pipeline also passes full generic synthesis. This does not claim a generic
flop/ABC implementation of the full RAM design. Controller BMC passes depth32;
the final physical core BMC passes depth48 with eight assertions. A deliberate
negative control fails with its counterexample. These bounded control checks
are not a proof of full-layer liveness or all arithmetic inputs.

Retained unsuccessful attempts include: initial unused-node export failures;
distributed RAM overuse through four CAD arrangements; RAM inference probes;
Yosys optional-share undriven-bit failure (optimizer omitted, structural checks
retained); formal wrapper parse errors; a real stalled-request payload
counterexample fixed by separating read-owner data; unchanged depth48 formal
timeouts followed by a larger wall-clock budget; Verilator filename packaging
failure fixed without lint suppression; negative-hold 25 MHz and 20 MHz builds
that were never programmed; Tcl 8.5 codec incompatibility; first Linux C probe
failure; and the evidence auditor's repeated timing-header parse failure.
No failed build is presented as qualified and no numerical tolerance or formal
assertion was weakened to obtain a pass.

All **352 protected production/interface files are byte-identical** to their
pre-task inventory. The old integer target's 18 exported files and previous
floating-point target's 16 files are byte-identical to their prior evidence.
The new target's 16 exported files are reproducible. Existing user work was
preserved. Historical host status and recovery records remain intact; the
integer-unchanged statement is scoped to this task.
